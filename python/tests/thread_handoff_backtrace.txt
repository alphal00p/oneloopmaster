Independent sequential-thread crash diagnosis (2026-09-08)
========================================================

Reproducer: python/tests/thread_handoff.py
Both workers request 128 MiB stacks and run strictly sequentially.
Worker 1 imports the extension, evaluates A0(2), and exits.
Worker 2 reimports the cached module and calls Evaluator("A0").

  SymJIT 2.24.1, strict-v3 patches
  mimalloc 0.1.52 / libmimalloc-sys 0.1.49 (enabled by Symbolica faster_alloc)
  Debug Python extension, CPython 3.13.12, x86_64 Linux

BEFORE the Rust Evaluator::new body, cache cloning, or generated code execution.

No large core dump is retained.

Configuration repair and direct verification:
  Both core and Python manifests disable Symbolica's default features and
  explicitly retain bincode, float-mpfr, integer-gmp, native_code_generation,
  and tracing_max_level_info. The faster_alloc global allocator is excluded.
  cargo tree -e features -i symbolica confirms exactly those five features;
  cargo tree -i mimalloc reports no matching package.
  After rebuilding the debug extension, the UNCHANGED two-worker reproducer
  exits successfully: the second worker constructs and drops all five families.
  No evaluator-thread guard, evaluator lifetime change, or mathematical change
  is used to obtain this result.

Full API regression after rebuilding, using the original fresh-worker mode:
  env -u ONELOOP_PYTHON_REBUILD -u SYMJIT_TOML \
      ONELOOP_PYTHON_THREAD_HANDOFF=1 PYTHONPATH=<extension directory> \
      python3 -X faulthandler -m unittest discover -s python/tests \
      -p test_api.py -v
  Result: all 7 tests PASS in 107.040 seconds. This includes cold main-thread
  subprocesses, environment guards, all shared fixtures, invalid inputs,
